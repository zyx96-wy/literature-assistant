## D.3 Zotero 详细分析

### D.3.1 核心能力

- 一键抓取网页元数据（DOI、作者、PDF）
- 支持 9000+ 引用格式，与 Word / Google Docs 深度集成
- 插件生态极其活跃，社区贡献大量增强功能

### D.3.2 AI 策略

Zotero 本身不做 AI，靠插件生态和外部工具桥接：

| 插件 | 作用 |
|---|---|
| Zotero-AI-Butler | 后台自动精读入库文献，生成结构化笔记，下载量超 18 万次 |
| Beaver（哈佛团队开发中） | 内嵌 AI 研究 Agent，agentic RAG，返回页码级引用 |
| zotero-gpt | 直接调用 LLM 对选中文献对话 |

### D.3.3 可借鉴点

- **数据沉淀**：条目、附件、注释、集合，本身就是 RAG 检索的元数据过滤维度
- **平台策略**：不做 AI，做平台，AI 能力由插件消费数据实现
- **数据结构**：条目 / 附件 / 注释 / 集合，是我们参考的数据结构来源

### D.3.4 缺口

- 笔记与 AI 分离
- 问答一次性，不留痕迹
- 无共识度量
- 流程透明度依赖插件，参差不齐

## D.4 Mendeley 详细分析

### D.4.1 核心能力

- 文献存储、组织、标注、引用
- 与 Word 集成生成参考文献
- AI 功能：Reading Assistant、Ask My Library、Compare Experiments

### D.4.2 Ask My Library 技术实现

明确使用 RAG：

```
查询优化 → 安全审查 → 向量搜索（语义相似度）
  → 检索片段送入 LLM → 生成带引用的回答
```

- 每次返回最多 20 篇相关文档
- 并非全部会被 LLM 使用

### D.4.3 关键局限

| 局限 | 说明 |
|---|---|
| 仅支持 PDF | 不支持表格、图片、扫描件 |
| 无过滤 | 无法按集合或指定文献过滤 |
| 查询限制 | 单次查询 500 字符 |
| 移动端 | 已停用 |
| 非英语 | 支持有限 |
| 无插件生态 | AI 能力完全依赖 Elsevier 官方 |

### D.4.4 可借鉴点

- **库内 RAG 工程实现**：查询优化 → 向量搜索 → 生成，链路清晰
- **反面教材**：仅 PDF、无过滤、无插件，说明文献 RAG 的难点不在模型，在文档解析和元数据整合

### D.4.5 缺口

- 笔记弱
- 问答一次性
- 无共识度量
- 封闭生态，灵活性差

## D.5 Elicit 详细分析

### D.5.1 核心工作流

| 工具 | 作用 |
|---|---|
| Find Papers | 语义搜索 1.38 亿论文，自然语言提问返回相关文献表格 |
| Chat with Papers | 对上传的 PDF 对话（Basic 最多 4 篇，付费 8 篇） |
| Extract Data | 从 PDF 提取结构化数据（方法、样本、结果等） |
| Systematic Review | 引导式系统综述流程：搜索 → 筛选 → 数据提取 → 生成报告 |
| Research Report | 自动生成研究报告，每个声明带原文引用 |

### D.5.2 Systematic Review 的 RAG 逻辑

- 输入研究问题，系统建议筛选标准和提取字段
- 支持上传 PDF + 语义搜索补充
- 按「符合筛选标准的概率」排序论文，人工可覆盖 AI 判断
- 数据提取时提供支持性引文和解释，方便核查
- 整个项目可分享、可迭代，支持 living reviews

### D.5.3 自我评测

17 名 PhD 级研究者对 29 个问题生成报告，Elicit 在准确性和实用性上显著优于 OpenAI、Perplexity、Gemini 的 Deep Research 工具。

### D.5.4 可借鉴点

- **流程透明度**：每一步都让用户看到中间结果，可覆盖 AI 决策
- **Human-in-the-loop**：搜索、筛选、提取都可审查，是文献场景刚需
- **可迭代**：living reviews，项目可分享、可迭代

### D.5.5 缺口

- 问答一次性，不留痕迹
- 无个人笔记沉淀
- 无共识度量
- 偏系统综述，不覆盖日常阅读

## D.6 Consensus 详细分析

### D.6.1 核心工作流

```
广泛召回（语义 embeddings + BM25 关键词）扫描 2.2 亿论文
  → 取 top 1500，按发表时间、引用数、期刊影响力重排
  → 用更强 AI 模型对 top 20 论文重新排序
     （结合相关性 + 学术质量）
```

### D.6.2 标志性功能

| 功能 | 说明 |
|---|---|
| Consensus Meter | 对 Yes/No 问题，可视化文献中的支持 / 反对比例 |
| Pro Analysis | 综合 top 论文的发现，生成带引用的高层总结 |

### D.6.3 RAG 设计哲学

- **先搜索，后生成**：「我们是一个搜索引擎，不是聊天机器人」
- **只摘要，不推测**：AI 严格限制在检索到的论文内容内，不「脑补」
- **Checker 模型**：摘要前用独立模型验证来源相关性，不相关的不进入生成
- **三类幻觉中，只可能有一类**：假来源和纯记忆胡编不可能发生，只有「误读来源」可能

### D.6.4 可借鉴点

- **共识度量**：把「共识」产品化，输出比例而非一段话
- **Checker 模型**：生成前独立验证来源相关性
- **搜索优先**：不做通用聊天，定位清晰

### D.6.5 缺口

- 问答一次性，不留痕迹
- 无个人笔记沉淀
- 不覆盖个人文献库
- 不生成综述

## D.12 参考组合

| 来源 | 借鉴 |

**一句话**：

> Zotero 的数据结构 + Elicit 的流程透明度 + Consensus 的共识度量输出 + 笔记可沉淀。

## D.15 一句话结论

> Zotero 管文献，Mendeley 做库内 RAG，Elicit 做系统综述，Consensus 给共识。
>
> 它们各自最强的地方，我们借鉴；它们共同的缺口——**笔记沉淀、知识复用、流程透明、可积累**——是我们的机会。
>
> 我们不做聊天框，做可审查、可追溯、可量化、可积累的研究流程。
