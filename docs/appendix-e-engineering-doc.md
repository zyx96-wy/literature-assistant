> 本附录说明 SKILL 与 PRD 的分工关系，属工程实现层文档。

## E.1 这份附录解决什么

PRD 是产品文档，回答「为什么做、做什么、做到什么程度」。但系统里还有一份 `SKILL.md`，是给 Agent 看的执行说明书。两者受众不同、职责不同，容易混淆。这份附录说清 SKILL 的定位，以及它和 PRD 的关系。

---

## E.2 SKILL 是什么

`SKILL.md` 是**给 Agent 看的执行说明书**，包含：

| 内容 | 例子 |
|---|---|
| 触发词 | 上传文献、arXiv、深解析 |
| 意图路由表 | 用户说什么 → 执行什么命令 |
| 命令速查 | `add` / `ask` / `review` |
| 工作流细则 | 深解析、翻译、问答、综述 |
| 数据结构 | 文件路径、字段 |
| 边界声明 | 不编造、不联网 |
| 版本历史 | v5.0.0 变更 |

**它是「怎么实现」的文档，不是「为什么做」的文档。**

---

## E.3 SKILL 和 PRD 的关系

```
PRD（为什么做、做什么、做到什么程度）
  ↓
SKILL（怎么实现、命令是什么、流程是什么）
  ↓
代码（真正跑起来的东西）
```

| 维度 | PRD | SKILL |
|---|---|---|
| 受众 | 产品、设计、开发、测试、业务 | Agent、开发者 |
| 回答 | 为什么做、做什么 | 怎么实现 |
| 粒度 | 需求级 + 验收级 | 功能级 |
| 变更 | 随产品决策 | 随代码迭代 |

**PRD 是产品文档，SKILL 是工程文档。两者不冲突，但受众不同。**

---

## E.4 建立顺序说明

正常顺序：

```
1. 想法
2. PRD（为什么做、做什么）
3. 技术方案（怎么做）
4. 开发（写代码）
5. 工程文档（SKILL 这类）
6. 验收（对照 PRD）
```

本项目的顺序：

```
1. 想法
2. SKILL（先做出来了）
3. PRD（现在在补）
4. 开发（待做）
5. 验收（待做）
```

**属于「先做后补」，不算错，但要把 PRD 补扎实，否则产品逻辑站不住。**

---

## E.5 SKILL 的后续角色

| 阶段 | SKILL 的角色 |
|---|---|
| 现在 | 唯一的实现文档 |
| PRD 完成后 | 工程实现文档，PRD 的下游 |
| 开发完成后 | 开发参考，代码的上游 |
| 作品集 | 展示工程能力的证据 |

**它不是「不要」，是「从主文档降为工程文档之一」。**

---

## E.6 SKILL 的处理建议

| 处理 | 说明 |
|---|---|
| 保留 | 作为工程实现文档 |
| 降级 | 从主文档降为附录或独立文档 |
| 对齐 | 确保 SKILL 和 PRD 不冲突 |
| 精简 | 把产品逻辑移到 PRD，SKILL 只留实现 |
| 版本化 | SKILL 和 PRD 各自版本记录 |

## E.7 文档分工

| 文档 | 职责 | 受众 |
|---|---|---|
| `PRD.md` | 产品定义 | 产品、设计、业务 |
| 附录 A | 数据结构 | 开发 |
| 附录 B | 命令速查 | 开发、测试 |
| 附录 C | 验收清单 | 测试 |
| 附录 D | 竞品详细对比 | 产品、战略 |
| 附录 E | 工程实现文档（本附录） | 开发、面试 |
| `SKILL.md` | Agent 执行说明书 | Agent、开发 |

## E.8 版本独立

| 文档 | 版本管理 |
|---|---|
| PRD | 独立版本记录（第 22 章） |
| SKILL | 独立版本记录（SKILL 内） |

**两者版本独立，不强制同步。**

---

## E.9 面试时的表述

> 我先用 SKILL 把原型跑通，再补 PRD 把产品逻辑立住。
> SKILL 是工程文档，PRD 是产品文档，两者分工明确。
> SKILL 是 PRD 的下游，代码的上游。

---

## E.10 不做

| 不做 | 为什么 |
|---|---|
| 不把 SKILL 当产品文档 | 受众不同，职责不同 |
| 不强制同步版本 | 各自独立 |
| 不删 SKILL | 它是工程实现文档，有价值 |
| 不把产品逻辑留在 SKILL | 产品逻辑应移到 PRD |
