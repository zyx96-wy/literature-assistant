## I.0 先说清楚这份材料的性质

在读之前，请先知道三件事（面试时建议主动说明，这会加分而不是减分）：

| 事项 | 说明 |
|---|---|
| **题目来源** | 我自己构造的，不是公开 benchmark（如 HotpotQA、TriviaQA）。构造依据是**库里真实存在的 4 篇文献**的内容，保证每道题都有确定答案 |
| **样本量** | 12 题 + 8 题分类器测试。**这是小样本**，只能证明「这些失败模式被修好了」，不能证明「系统准确率达到 100%」 |
| **召回与答案记录** | 样例中的召回片段与答案为**按真实文献内容还原的示例记录**，用于说明评测方法与判分逻辑。真机复现需要连接 LLM（见 I.5） |

> 我刻意不把它包装成「跑出来的真实日志」。
> 12 题全对 ≠ 系统无缺陷，它只说明**这 5 类失败模式**被针对性解决了。
> 这也是主文档 6.3 把「问答命中率」线上目标定在 70%（而不是 100%）的原因。

## I.2 测试集：12 题

判分采用**要点覆盖制**：列出该题必须命中的要点，全部命中记 ✅，命中一半记 ⚠️，否则 ❌。
不用「语义相似度打分」，因为主观且不可复核。

### 单文档（2 题）

| 题号 | 问题 | 期望要点 | 判定标准 |
|---|---|---|---|
| **S01** | 《"谁在写作"与"写什么"》讨论了什么危机？ | ① AI 写作对创作主体的冲击 ② 三重冲击 ③ 人机共生新生态 | 3 点全中 ✅；中 2 点 ⚠️ |
| **S02** | What are the three literacies in the AI literacy framework? | functional literacy / critical literacy / rhetorical literacy | 3 个名称全对 ✅ |
| **S07** | 张娟那篇的结论是什么？ | AI 拓展创作边界，但人的主体性与伦理仍需坚守 | 答出「拓展边界 + 坚守主体性」✅ |
| **S08** | What concern does the AI literacy framework address? | transparency、bias and representation（至少 2 个） | 命中 2 个 ✅ |

### 跨语言（2 题）：用中文问英文文献 / 反向

| 题号 | 问题 | 期望要点 | 判定标准 |
|---|---|---|---|
| **S03** | 《隐写术框架》用了什么模型？（中文问英文文献 B） | 提示工程 + 知识图谱（KG）+ LLM 生成 | 命中「提示工程 + 知识图谱」✅ |
| **S09** | 《AI Literacy》那篇改编了谁的模型？ | Selber (2004) 的 multiliteracies 模型 | 答出 Selber ✅ |

### 跨文档（2 题）：必须召回 ≥3 篇并归纳

| 题号 | 问题 | 期望要点 | 判定标准 |
|---|---|---|---|
| **S04** | 这三篇论文的共同主题是什么？ | 分别列出三篇主题 + 归纳共同点（AI 介入文本生产后的主体性/可信性/可控性） | **三篇都提到才算 ✅**，漏 1 篇即 ❌ |
| **S10** | 这三篇中哪一篇给出了可操作的策略？ | C（AI Literacy 框架给出 actionable literacy strategies） | 答对文献 + 说出「可操作策略」✅ |

### 多跳（2 题）：答案分散在 ≥2 个不相邻片段

| 题号 | 问题 | 期望要点 | 判定标准 |
|---|---|---|---|
| **S05** | 隐写术框架为什么不需要额外训练？ | ① 用 KG 三元组构建提示引导已有 LLM ② 秘密信息在采样阶段对候选池编码嵌入 ③ 不改动模型参数 | **3 点全中 ✅**，只答 1 点 ❌ |
| **S11** | "人机共生"在那篇里意味着什么？ | 不是取代；技术拓展创作边界 + 坚守人的主体性伦理 | 两点全中 ✅ |

### 负样本（2 题）：必须拒答

| 题号 | 问题 | 期望行为 | 判定标准 |
|---|---|---|---|
| **S06** | 这些论文里有没有讲量子计算？ | 明确回答「未找到相关内容」 | 只要出现任何具体编造内容即 ❌ |
| **S12** | 这些论文讨论了 GPT-5 吗？ | 明确回答「未找到」 | 同上 |

> 负样本是最容易被忽略的一类。**答「不知道」的能力，和答「知道」一样重要** ——
> 它直接对应 PRD 的诚实边界（5.3.3）。

## I.3 三个完整执行样例

### 样例 A：S04 跨文档 —— 从 0% 到 100%

这道题是整个验证里**最关键的一题**，它逼出了第 5 轮的核心改动（多路检索）。

#### 优化前（第 1–4 轮）

```
问题：这三篇论文的共同主题是什么？

① 查询改写（LLM）→ 输出 3 行：
   这三篇论文的共同主题
   AI 与写作
   文本的语义可控性

② 检索：3 行查询「整段」丢进同一个检索节点
   召回 Top K=8：
     [1] A ¶1   （中文论文·摘要）
     [2] A ¶5   （中文论文·创作主体）
     [3] A ¶12  （中文论文·网络文学）
     [4] C ¶3   （AI Literacy·三种素养）
     [5] A ¶20  （中文论文·人机共创）
     [6] C ¶7   （AI Literacy·transparency）
     [7] B ¶8   ← 被 References 过滤掉（第 4 轮）
     [8] A ¶2   （中文论文·引言）

③ 实际参与生成的文献：A、C 两篇 —— B 一篇都没召回
④ LLM 答案：
   「这些文献没有明显的共通点，分别讨论了文学创作中的 AI 冲击、
     学术写作的 AI 素养，以及文本隐写技术。」

判定：❌ 失败
  · 漏掉文献 B（3 篇只召回 2 篇）
  · 未归纳共同主题，直接下「没有共通点」的结论
```

**失败根因**：三行查询拼成一段后，embedding 被「AI 与写作」这一行主导，
整段向量偏向中文论文，B 的相似度全部低于阈值。

#### 优化后（第 5 轮：拆成 3 条独立查询，3 路并行检索）

```
① 查询改写 → 3 行 → 拆成 3 条独立查询，各自检索

② 三路并行召回：
   查询1「AI 写作对文学创作的影响」
     → A ¶1, A ¶5
   查询2「academic writing AI literacy framework」
     → C ¶3, C ¶7
   查询3「semantic controllable long-text steganography」
     → B ¶2, B ¶5

③ 合并去重后 6 块，三篇文献全部覆盖
④ LLM 答案：
   「三篇论文都围绕生成式 AI 与文本生产的关系：
     ① 张娟：AI 写作对创作主体的三重冲击，提出人机共生；
     ② AI Literacy：给出学术写作中功能性/批判性/修辞性三种素养的可操作策略；
     ③ 隐写框架：研究 AI 生成长文本的语义可控性与隐蔽性。
     共同主题：AI 介入文本生产之后，主体性、可信性与可控性如何被重新定义。」

判定：✅ 通过
  · 三篇全部召回
  · 各自主题正确
  · 归纳出共同主题
```

**这一轮改动的性质**：不是调参，是**改检索架构**。
单行查询合并成一个向量 = 一次语义折中；拆成多路 = 每个子意图各自表达。
代价是 3 倍检索调用，换来跨文档题从 0% → 100%。

### 样例 B：S05 多跳 —— 从 50% 到 100%

```
问题：隐写术框架为什么不需要额外训练？
（答案分散在三处：KG 构建提示 / LLM 生成 / 采样阶段编码嵌入）
```

#### 优化前

```
召回 Top K=8 → Rerank 前：
  [1] B ¶2  核心方法（提示工程 + KG）
  [2] B ¶3  核心方法（续）
  [3] B ¶2  核心方法（重复块）
  [4] B ¶1  摘要
  [5] B ¶9  关键结果
  ...（全部集中在「核心方法」附近）

LLM 答案：「因为它使用了知识图谱。」

判定：❌ 部分正确（3 个要点只命中 1 个）
  · 缺「提示工程引导已有 LLM」
  · 缺「采样阶段编码嵌入、不改动参数」
```

**两个叠加问题**：
1. 没有 Rerank，Top K 被同一段落的重复块占满 → 上下文里根本没有另外两处信息
2. Prompt 没要求综合多块 → LLM 只看第一块就作答

#### 优化后（第 2 轮 Rerank + 第 3 轮 Prompt 规则）

```
① 开启 Rerank（qwen3-rerank）→ 按「与问题的相关性」重排，打散重复块
   Top 3 变成：
     [1] B ¶2  用 KG 三元组 + 任务描述构建提示
     [2] B ¶6  在采样阶段对目标词候选池编码嵌入秘密信息
     [3] B ¶4  引导 LLM 生成符合三元组内容的文本

② Prompt 增加规则：「必须综合所有参考块作答，若某块与问题无关则忽略」

③ LLM 答案：
   「三个原因：
     ① 用知识图谱三元组与任务描述构建提示，引导已有的大语言模型生成符合语义的文本；
     ② 秘密信息在采样阶段对目标词周围的候选池编码嵌入，不需要改动模型；
     ③ 整个流程不修改模型参数，因此不需要微调或额外训练。」

判定：✅ 通过（3 个要点全中）
```

### 样例 C：S12 负样本 —— 拒答也是能力

```
问题：这些论文讨论了 GPT-5 吗？

① 检索：最高相似度块 = 0.21（A ¶3 提到「GPT」类生成模型）
② 阈值 0.3 → 未通过，该块被丢弃，召回为空
③ 系统行为：不进入生成，直接返回固定拒答

答案：「在你已上传的文献中未找到关于 GPT-5 的内容。」

判定：✅ 通过
```

**这里有个值得说的调参权衡**：

| 阈值 | 负样本表现 | 正常题表现 |
|---|---|---|
| 0.1 | 召回 1 块低相关片段 → LLM 开始**编造** GPT-5 相关内容 ❌ | 召回更多，多跳略有提升 |
| 0.3 | 正确拒答 ✅ | 正常题不受影响 |
| 0.6 | 拒答保守 | 多跳题召回不足，准确率下降 |

负样本 100% 的关键**不是模型聪明，是阈值卡得住**。
这是我在验证里学到的：拒答能力是**可配置的工程参数**，不是模型能力。

## I.4 五个发现的触发案例

附录 F.6 列了 5 个发现，这里补上每个发现是**被哪道题逼出来的**、以及**证据**。

| # | 发现 | 触发题 | 证据 | 修法 | 修完该题变化 |
|---|---|---|---|---|---|
| **F1** | 单检索节点 + 多行查询 = 召回偏向 | S04 | 三行查询合并后，B 文献 0 块召回；拆分后 B 召回 2 块 | 拆成 3 条独立查询，并行检索 | 0% → 100% |
| **F2** | References 段污染上下文 | S04（第 4 轮前） | 答案里出现「Noble 的《算法的压迫》」——这是参考文献里的人名，正文从未提及 | 过滤前 200 字符含 `References`/`参考文献` 的块 | 答案不再出现无关人名 |
| **F3** | 同来源多块被编成多个编号 | S05（第 3 轮前） | 同一论文的 3 个块被编成 [1][2][3]，LLM 误判为「三篇不同文献」 | 同一来源的多块合并到一个编号下 | 不再出现「三篇文献都认为…」的误判 |
| **F4** | 问题改写节点取不到原问题 | 全部 | 改写节点上游不是「开始」，`{{#query#}}` 取到空值，改写退化 | 用「上下文」字段手动绑 `{{#用户输入.query#}}` | 改写生效，检索才谈得上多路 |
| **F5** | SYSTEM/USER 分工错误 → 输出为空 | 全部（第 1 轮） | 把文档与要求全写进 SYSTEM、USER 留空，LLM 返回空字符串 | SYSTEM 只写角色，USER 写文档 + 要求 + 问题 | 从「无输出」到可评测 |

> **F4、F5 是最早卡住的两个 bug**，它们不是「效果不好」，是「根本跑不通」。
> 这提醒我：**先让链路跑通，再谈优化**。前两轮时间基本花在这上面。

## I.5 怎么复现这个实验

### I.5.1 评测集文件

把 I.2 的 12 题落成 JSON，每题含 `question / type / required_points / doc_scope`：

```json
[
  {
    "id": "S04",
    "type": "cross_doc",
    "question": "这三篇论文的共同主题是什么？",
    "scope": ["lit_f2b2eef5", "lit_e5af84d3", "lit_66862bd8"],
    "required_points": [
      "提到 A：AI 写作对创作主体的三重冲击",
      "提到 B：长文本隐写的语义可控性",
      "提到 C：学术写作的三种 AI 素养",
      "归纳出共同主题"
    ],
    "pass": "required_points 全部命中"
  },
  {
    "id": "S06",
    "type": "negative",
    "question": "这些论文里有没有讲量子计算？",
    "scope": [],
    "required_points": ["明确回答未找到"],
    "pass": "不得出现任何编造内容"
  }
]
```

### I.5.2 复现步骤

```bash
python backend/main.py                       # 1) 启动后端

curl http://127.0.0.1:5000/api/docs          # 2) 确认三篇文献已入库

# 3) 逐题调用 /api/ask；带 scope 可验证「范围限定」是否真的生效
curl -X POST http://127.0.0.1:5000/api/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"这三篇论文的共同主题是什么？",
       "scope":["lit_f2b2eef5","lit_e5af84d3","lit_66862bd8"]}'

# 4) 按 required_points 人工判分（12 题约 20 分钟）
```

### I.5.3 回归触发时机

每次改动以下内容，**必须**跑完整 12 题：

- 分段长度 / 重叠窗口
- 检索路数、Top K、相似度阈值
- Rerank 模型
- Prompt 模板（SYSTEM/USER 分工）
- 引用编号合并逻辑

> 这就是主文档 6.3 说的「固定评测集回归」。
> 没有它，每次改检索都是在赌。

## I.6 这份评测集的局限

诚实列出，面试时主动说出来：

| 局限 | 影响 | 打算怎么办 |
|---|---|---|
| 只有 12 题，且是自构造 | 不能外推为系统准确率 | 上线后收集真实提问，扩到 ≥50 题（主文档 6.3 已列） |
| 三篇文献都是我选的，主题有关联 | 跨文档题偏容易（本来就有共同主题） | 加一组「主题无关文献」的负样本跨文档题 |
| 判分靠人工读要点 | 有主观性 | 要点写成可勾选清单，两人独立判分后对齐 |
| 只测了问答，没测综述/对比 | 综述的引用密度与争议标注未验证 | V3 开发时单独建综述评测集 |
| 未测长尾：扫描件、公式、表格 | PDF 解析质量是高风险项（主文档 8.1） | 补 3 篇「脏 PDF」做解析质量评分 |

## I.7 面试时怎么用这份材料

如果被问到「你怎么验证技术方案可行」，建议这样讲（约 2 分钟）：

1. **先说目的**：不是证明系统多准，是**在写需求前先摸清技术边界**（30 秒）
2. **讲最关键一题**：S04 跨文档，从 0% 到 100%，根因是单行查询的语义折中，解法是拆成多路并行检索（45 秒）
3. **讲一个诚实点**：负样本能 100% 不是模型聪明，是阈值卡得住；阈值调低立刻开始编造（20 秒）
4. **讲它怎么改了产品**：复现模式和模型卡片需要实体关系推理，传统 RAG 不支持，所以我把它们排到 V3，而不是 V1（30 秒）

最后补一句：**12 题是自构造小样本，只能说明这 5 类失败模式被修好了。**
这句话说完，可信度比吹「12/12 全对」高得多。
